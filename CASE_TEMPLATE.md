# Как добавить проект в портфолио

Все проекты лежат в `lib/projects.ts`. Сайт сам раскладывает их по трём
разделам по полю `track`:

| `track`    | Раздел на сайте        | Что туда класть                               |
| ---------- | ---------------------- | --------------------------------------------- |
| `work`     | A / Work projects      | проекты по работе, в лаборатории, в команде   |
| `personal` | B / Personal projects  | свои проекты, которые ты собрала сама          |
| `idea`     | C / Ideas & concepts   | идеи и концепты: рендеры, эскизы, без железа  |

Есть два уровня готовности.

1. **Черновик** (`projectDrafts`): карточка с проблемой, идеей, инструментами
   и рамкой «Image in progress». Нужен, когда проект реальный, а фото и
   полного описания ещё нет.
2. **Полный кейс** (`projects` + ключ в `featuredProjectOrder`): большая
   карточка с картинкой и историей из пяти глав.

## Структура полного кейса (как в MIT Maker Portfolio)

| Глава на сайте      | Поле             | Что написать                                                                          |
| ------------------- | ---------------- | ------------------------------------------------------------------------------------- |
| 01 The problem      | `problem`        | Что не так или чего не хватает, у кого и почему это важно. 2–3 предложения.          |
| 02 The idea         | `solution`       | Какое решение ты придумала и почему именно такое.                                     |
|                     | `overview`       | Честные рамки: что уже сделано, а что пока нет.                                       |
|                     | `role`           | Что делала именно ты. Особенно важно для рабочих проектов.                           |
| 03 How I built it   | `development`    | 3–5 шагов. У каждого шага можно указать `image` с фото процесса.                     |
| 04 The result       | `result`         | Что работает сейчас, с цифрами: время, количество, размеры, тесты.                    |
|                     | `details`        | Таблица характеристик: компоненты, размеры, параметры.                                |
|                     | `evidence`       | `verified`: что уже доказано; `next`: что ещё нужно показать.                         |
| 05 What I learned   | `learned`        | 2–3 вывода своими словами: что пошло не так и что ты теперь делаешь иначе.            |
|                     | `nextStep`       | Следующий шаг проекта.                                                                |

Совет из MIT-портфолио: неудачи и переделки — это плюс. Шаг «первая версия
корпуса не влезла, переделала крепления» говорит о тебе больше, чем идеальный
рендер.

## Какие фото снимать для каждого проекта

- [ ] **Главное фото или рендер** (для карусели, 1600 px по ширине, `.webp`)
- [ ] **Эскиз или первая идея**: фото блокнота, доска, схема
- [ ] **CAD**: скриншот модели, сборки, разреза, чертежа
- [ ] **Процесс**: макетная плата, пайка, 3D-печать, примерка
- [ ] **Неудачная версия**: Rev A рядом с Rev B
- [ ] **Готовый результат в руке или в работе**: видно масштаб и что оно работает

Картинки клади в `public/media/<имя-проекта>/`. Сжать в webp:

```bash
convert photo.jpg -resize 1600x -quality 82 public/media/my-project/hero.webp
```

## Как превратить черновик в полный кейс

1. Добавь ключ проекта в `PROJECT_KEYS`.
2. Перенеси данные из `projectDrafts` в `projects` и заполни все главы.
3. Добавь ключ в `featuredProjectOrder` (в нём задаётся порядок на странице).
4. По желанию задай цвет акцента в `projectColors`
   (`components/PortfolioExperience.tsx`).
5. Проверь: `npm run check && npm run lint`.
